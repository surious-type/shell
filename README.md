# Учебный командный интерпретатор Shell

Упрощённый Unix-подобный командный интерпретатор на языке C. Проект выполнен в рамках задания **Task 5 (Shell)** спецкурса по операционным системам.

Интерпретатор читает команды из стандартного ввода, выполняет лексический и синтаксический анализ, строит дерево команд и запускает процессы средствами POSIX. Поддерживаются конвейеры, перенаправления потоков, логические операторы, фоновое выполнение и вложенные группы команд.

> **Примечание:** это учебный интерпретатор, а не полная реализация Bash. Сейчас включён отладочный вывод: перед исполнением каждой команды печатаются список лексем и структура дерева. Поэтому результаты тестов сопровождаются диагностическими строками.

## Сборка и запуск

Нужны компилятор C с поддержкой POSIX, `make` и Unix-подобная среда (например, Linux или Termux). Для проверки примеров должны быть доступны стандартные утилиты `echo`, `cat`, `grep`, `wc`, `sleep`, `true`, `false` и `pwd`.

```sh
make
./shell
```

После запуска появляется приглашение `$ `. Все команды из раздела **«Проверка функциональности»** нужно вводить **внутри запущенного `./shell`**, по одной строке.

Другие цели Makefile:

```sh
make clean      # удалить объектные файлы и исполняемый файл
make           # собрать ./shell
make asan      # пересобрать с AddressSanitizer и UndefinedBehaviorSanitizer
make run       # запустить через rlwrap (если утилита установлена)
```

`make asan` делает очистку и собирает инструментированную версию программы. Для возврата к обычной сборке выполните `make clean && make`.

Выход из интерпретатора — команда `exit` или **Ctrl-D** на пустой строке.

## Реализованный функционал

| Возможность | Описание |
| --- | --- |
| Простые внешние команды | Запуск программ с произвольным числом аргументов через `fork()` и `execvp()`; поиск исполняемых файлов с использованием `PATH`. |
| Встроенные команды | `cd [каталог]` (без аргументов — переход в `$HOME`) и `exit`. |
| Конвейеры `\|` | Произвольное количество команд, соединённых с помощью `pipe()` и `dup2()`; стадии запускаются как отдельные процессы. |
| Перенаправление `<` | Стандартный ввод команды из файла. |
| Перенаправление `>` | Стандартный вывод в файл с созданием/очисткой файла. |
| Перенаправление `>>` | Стандартный вывод в файл с добавлением в конец. |
| `&&` | Следующая команда выполняется только при успешном завершении предыдущей. |
| `\|\|` | Следующая команда выполняется только при неуспешном завершении предыдущей. |
| `;` | Последовательное выполнение независимо от кода завершения. |
| `&` | Фоновый запуск команды, конвейера или группы `&&`/`\|\|` без ожидания в основном shell. |
| Фоновые процессы | Игнорирование `SIGINT` в фоновой группе, перенаправление её stdin на `/dev/null`, учёт PID и неблокирующая уборка завершившихся потомков через `waitpid(..., WNOHANG)`. |
| Скобки `( ... )` | Выполнение вложенного списка команд в отдельном процессе (subshell), в том числе в конвейерах. |
| Лексический анализ | Разделение на слова и операторы; пробелы, табуляция, кавычки, обратный слеш, комментарии `#`; распознавание `>>`, `&&`, `\|\|`. |
| Подстановка значений | `$HOME`, `$USER`, `$EUID`, `$SHELL`, в том числе внутри слова (`$HOME/test`). |
| Обработка ошибок | Диагностика ряда лексических и синтаксических ошибок, ошибок открытия файлов и запуска программ. |
| Отладочная печать | Печать лексем и дерева команд перед выполнением. |

**Коды завершения:** `0` означает успешное выполнение; ненулевое значение — неуспех. Для конвейера используется статус **последней команды**, при этом родитель ожидает дочерние процессы всех стадий.

## Грамматика реализованного языка (расширенная БНФ)

Ниже приведена грамматика, соответствующая уровням рекурсивного спуска в `tree.c`. Фигурные скобки `{ ... }` обозначают повторение **ноль или более раз**, квадратные `[ ... ]` — необязательный элемент, символ `|` между альтернативами в записи грамматики означает «или». Терминалы командного языка записаны в кавычках.

```ebnf
<shell>          ::= <command_list>

<command_list>   ::= <and_or>
                     { ( ";" | "&" ) <and_or> }
                     [ ";" | "&" ]

<and_or>         ::= <pipeline>
                     { ( "&&" | "||" ) <pipeline> }

<pipeline>       ::= <command>
                     { "|" <command> }

<command>        ::= <simple_command>
                   | "(" <command_list> ")" <redirects>

<simple_command> ::= <word> { <word> } <redirects>

<redirects>      ::= [ "<" <word> ]
                     [ ( ">" | ">>" ) <word> ]
```

`<word>` — одна лексема-слово, сформированная лексическим анализатором: имя программы, аргумент либо имя файла. Пробелы могут входить в слово при заключении его в кавычки или экранировании. Операторы `|`, `&&`, `||`, `;`, `&`, `<`, `>`, `>>`, `(`, `)` имеют отдельные лексемы.

**Важное ограничение синтаксиса:** перенаправления указываются после имени команды и её аргументов; допустимы не более одного `<` и одного `>` **или** `>>` в порядке «сначала ввод, затем вывод». Например, `cat < in.txt > out.txt` допускается, а перестановка в форму `cat > out.txt < in.txt` этим парсером не поддерживается.

**Приоритеты (от высокого к низкому):**

1. Аргументы команды и перенаправления `<`, `>`, `>>`.
2. Конвейер `|`.
3. Логические связки `&&`, `||` (один уровень, слева направо).
4. Разделители `;`, `&` (один уровень, слева направо).

Круглые скобки позволяют сформировать отдельный вложенный список команд. Например:

```sh
false || (echo fallback ; echo done)
```

Соответствие грамматики функциям парсера:

| Нетерминал | Функция в `tree.c` |
| --- | --- |
| `<shell>` | `com_sh()` |
| `<command_list>` | `com_list()` |
| `<and_or>` | `and_or()` |
| `<pipeline>` | `conv()` |
| `<command>` | `command()` |
| `<simple_command>` | `simple_com()` |
| `<redirects>` | `parse_redirects()` |

## Архитектура

```text
          ввод пользователя
                 |
             read_line()
                 |
          build_list()         list.c: разбор строки на лексемы
                 |
          change_list()        list.c: подстановка переменных
                 |
             com_sh()          tree.c: рекурсивный спуск
                 |
            дерево tree
                 |
          exec_com_sh()        exec.c: обход структуры команд
                 |
       fork / execvp / pipe / dup2 / waitpid
                 |
            clear_tree()
```

Основные модули:

| Файлы | Назначение |
| --- | --- |
| `main.c` | Интерактивный цикл: приглашение, чтение, вызов анализаторов и исполнителя. |
| `list.c`, `list.h` | Связный список лексем, лексический анализ, подстановка четырёх переменных. |
| `tree.c`, `tree.h` | Рекурсивный спуск, проверка синтаксиса, построение и освобождение структуры команд. |
| `exec.c`, `exec.h` | Запуск процессов, встроенные команды, перенаправления, конвейеры, фоновые группы, ожидание и уборка потомков. |
| `buff.c`, `buff.h` | Динамический символьный буфер для строк и лексем. |
| `strutils.c`, `strutils.h` | Копирование строк. |
| `Makefile` | Сборка проекта и режим с санитайзерами. |

В дереве команд используются указатели `pipe` (следующая стадия конвейера), `next` (следующий конвейер в списке или логической цепочке) и `psubcmd` (вложенный список в скобках). Поле `type` хранит связь `NXT`, `AND` или `OR`, а `backgrnd` — признак выполнения в фоне.

## Проверка функциональности

### Быстрый показ основных возможностей

После `./shell` можно последовательно ввести:

```sh
echo hello
echo hello | cat | wc -c
echo first > shell_demo_input.txt
echo second >> shell_demo_input.txt
cat < shell_demo_input.txt
false || echo RECOVERED
true && echo SUCCESS
(echo A ; echo B) | wc -l
sleep 2 &
echo FOREGROUND_CONTINUES
```

**Результат:** вывод `hello`, число `6`, содержимое файла из двух строк, сообщения `RECOVERED` и `SUCCESS`, число `2`, немедленный возврат приглашения после `sleep 2 &`. Лексемы и дерево также печатаются — это штатная отладка. Для уведомления о завершённом фоне через несколько секунд нажмите Enter.

### Подробные проверки

Все команды ниже вводятся **внутри `./shell`**. Они используют только стандартные утилиты Unix и временные файлы `shell_demo_*.txt` в текущем каталоге. Из-за включённой отладки перед полезным результатом будут напечатаны лексемы и дерево.

### 1. Простые команды и аргументы

```sh
pwd
echo hello
echo "hello world"
echo 'hello world'
echo hello\ world
```

**Ожидается:** `pwd` печатает текущий каталог; команды `echo` печатают `hello` или `hello world`. Строка с обратным слешем перед пробелом передаёт `hello world` как один аргумент.

### 2. Комментарии и экранирование

```sh
echo before # this is a comment
echo "#not-a-comment"
echo \#escaped
```

**Ожидается:** `before`, `#not-a-comment` и `#escaped` соответственно. Неэкранированный `#` вне кавычек начинает комментарий.

### 3. Подстановка переменных

```sh
echo $HOME
echo $USER
echo $EUID
echo $SHELL
echo home=$HOME/subdir
echo $HOME/$USER
```

**Ожидается:** вместо известных последовательностей выводятся соответствующие значения. `$SHELL` в этой реализации определяется через `/proc/self/exe`, то есть показывает путь к текущей исполняемой программе shell, а не обязательно системную оболочку пользователя.

### 4. Перенаправления `<`, `>`, `>>`

```sh
echo first > shell_demo_input.txt
echo second >> shell_demo_input.txt
cat < shell_demo_input.txt
```

**Ожидается:** файл `shell_demo_input.txt` содержит две строки — `first` и `second`. `cat` их выводит.

Проверка именно очистки файла оператором `>`:

```sh
echo replacement > shell_demo_input.txt
cat < shell_demo_input.txt
```

**Ожидается:** в файле осталась только строка `replacement`.

### 5. Конвейеры `|`

```sh
echo hello | cat
echo hello | wc -c
echo hello | cat | wc -c
```

**Ожидается:** первая команда выводит `hello`; обе команды с `wc -c` выводят `6` (пять букв и символ перевода строки). Последний пример проверяет конвейер из трёх процессов.

Совместная проверка файлов и конвейера:

```sh
echo alpha > shell_demo_input.txt
echo beta >> shell_demo_input.txt
echo beta >> shell_demo_input.txt
cat < shell_demo_input.txt | grep beta | wc -l
```

**Ожидается:** `2` — число строк со словом `beta`.

Перенаправление вывода последней стадии конвейера:

```sh
echo hello | cat > shell_demo_pipe.txt
cat < shell_demo_pipe.txt
```

**Ожидается:** в файле `shell_demo_pipe.txt` лежит `hello`.

### 6. Логические операторы и `;`

```sh
true && echo AND_OK
false && echo SHOULD_NOT_APPEAR
false || echo OR_OK
true || echo SHOULD_NOT_APPEAR
echo FIRST ; echo SECOND
false && echo SKIPPED || echo RECOVERED
```

**Ожидается:** `AND_OK`, `OR_OK`, `FIRST`, `SECOND`, `RECOVERED`. Строка `SHOULD_NOT_APPEAR` не должна появляться **как результат выполнения `echo`**, но может присутствовать в отладочном выводе лексем и дерева.

Проверка того, что статус конвейера определяется его последней командой:

```sh
false | true && echo PIPE_SUCCESS
true | false || echo PIPE_FAILED
```

**Ожидается:** `PIPE_SUCCESS` и `PIPE_FAILED`.

### 7. Встроенная команда `cd`

```sh
pwd
cd ..
pwd
cd $HOME
pwd
```

**Ожидается:** текущий каталог меняется после `cd ..`, а `cd $HOME` возвращает в домашний каталог. Изменение каталога сохраняется между командами, поскольку обычный `cd` исполняется самим shell.

### 8. Скобки и subshell

```sh
pwd
(cd .. ; pwd)
pwd
(echo ONE ; echo TWO) | wc -l
```

**Ожидается:** `cd ..` внутри скобок влияет только на subshell, а третий `pwd` печатает тот же каталог, что и первый. Последний пример выводит `2`: две строки из вложенной группы поступают в конвейер.

```sh
(echo LEFT ; echo RIGHT) > shell_demo_group.txt
cat < shell_demo_group.txt
```

**Ожидается:** файл содержит `LEFT` и `RIGHT`.

### 9. Фоновое выполнение `&`

```sh
sleep 3 &
echo SHELL_IS_AVAILABLE
```

**Ожидается:** shell сразу показывает приглашение после `sleep 3 &`, не дожидаясь трёх секунд. Выполняется `echo SHELL_IS_AVAILABLE`. Через несколько секунд нажмите Enter: при очередной проверке завершившихся фоновых процессов появится сообщение вида `[background pid ... done]`.

Также можно проверить фоновый конвейер и отключение стандартного ввода:

```sh
sleep 2 | cat &
cat &
echo STILL_INTERACTIVE
```

**Ожидается:** shell остаётся интерактивным; фоновый `cat` не перехватывает ввод команд с клавиатуры, потому что его stdin подключён к `/dev/null`.

### 10. Обработка ошибочного ввода

Выполните по одной строке:

```sh
echo incomplete |
echo incomplete >
(echo unclosed
a_command_that_does_not_exist
```

**Ожидается:** сообщения о синтаксических ошибках или невозможности запустить программу. Интерпретатор не должен аварийно завершаться и должен продолжать принимать команды.

### 11. Завершение shell

```sh
exit
```

**Ожидается:** выход из интерпретатора. Альтернативно на пустом приглашении нажмите Ctrl-D.

После тестирования, уже из обычной системной оболочки, временные файлы можно удалить:

```sh
rm -f shell_demo_input.txt shell_demo_pipe.txt shell_demo_group.txt
```

## Известные ограничения

- Реализован только указанный выше учебный поднабор языка shell. Нет `for`, `if`, globbing (`*.txt`), общего механизма переменных shell и полноценного управления заданиями (`jobs`, `fg`, `bg`).
- Программа работает в интерактивном цикле чтения stdin; аргументы запуска вроде `./shell -c '...'` и исполнение файла команд через аргумент не реализованы.
- Парсер поддерживает перенаправления только в форме `[< файл] [> файл | >> файл]` после всех аргументов команды. Повторные перенаправления и обратный порядок отклоняются.
- Для самостоятельных встроенных команд `cd` и `exit` перенаправление стандартных потоков не применяется так же, как к внешним командам (например, `cd .. > file.txt` не создаст файл).
- Лексер удаляет кавычки и обратный слеш до подстановки переменных. Поэтому, в отличие от Bash, `$HOME` может раскрываться даже в одинарных кавычках или после экранирования `\$HOME`.
- Проверка завершения фоновых потомков выполняется при очередном проходе интерактивного цикла; уведомление об окончании может появиться не сразу после фактического завершения.
- Отладочная печать лексем и дерева включена намеренно и выводится на stdout.

## Основные системные вызовы

| Вызов / функция | Использование |
| --- | --- |
| `fork()` | Создание дочернего процесса. |
| `execvp()` | Замена программы дочернего процесса внешней командой. |
| `waitpid()` | Ожидание конкретного потомка и получение его статуса; `WNOHANG` для проверки без блокировки. |
| `pipe()` | Создание канала между процессами конвейера. |
| `dup2()` | Привязка стандартных дескрипторов `0`/`1` к файлам или концам канала. |
| `open()`, `close()` | Открытие/создание файлов и освобождение файловых дескрипторов. |
| `chdir()` | Изменение рабочего каталога для встроенной команды `cd`. |
| `signal()` | Обработка `SIGINT` самим shell и игнорирование его фоновыми процессами. |
